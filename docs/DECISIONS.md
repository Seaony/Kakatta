5. **（已被第 36 条取代，客户端以后再定）支持多种部署方式**：服务器 Docker + 网页端；桌面客户端（Mac / Windows / Linux）自带服务端在本机运行；手机客户端（iOS / 安卓）连接自建或官方服务端。客户端可以选择监控服务在本机、自己的服务器还是官方服务器上运行。详见 `VISION.md`。

10. **（已被第 36 条取代，客户端以后再定）开发顺序：先做服务端（Docker）和网页端，再做桌面端，最后做手机端。** 用户的 iOS 开发者账号还在申请。每一端都按最终形态做完整，不做临时版本。

12. **技术栈：服务端用 Go，浏览器自动化用 chromedp，前端用 React + Vite + TypeScript。** 用户同意用 Go，分析见 `TECH-STACK.md`。
13. **一个服务端只有一个登录账号**：用户名加密码，登录后能设置所有东西，不做多用户、不做权限管理。用户原话：「用户大多数时候就一个人用，搞那么复杂的账号体系没有意义」。注意区分：这里说的是登录 Kakatta 的账号；用来抓取的闲鱼账号仍然可以有多个。客户端（桌面端、手机端）登录后拿到的令牌不算多账号。
14. **开源许可证：MIT。**
15. **不假定服务端在什么环境里运行。** NAS、云服务器、家里的小主机、用户自己电脑上的 Docker 都要支持。用户原话：「你不要把服务器环境假定成某个环境」。因此：
    - Docker 镜像同时支持 amd64 和 arm64；
    - 内存要省，2GB 内存的 NAS 也要能跑；
    - 不依赖公网 IP，也不假定是家用网络还是机房网络；闲鱼访问可以配代理；
    - 数据都放在一个挂载目录里，适配 NAS 常见的用户和组 ID（PUID/PGID）设置；
    - 时区可以配置。
16. **尽可能轻量：内存、硬盘、运行时占用都要小。** 用户原话：「不能说我搞进去，然后哐当一下就几个 G，比如客户端就几个 G」「不要占用太大的内存、硬盘，或者运行时之类的资源」「但是要在保证功能的前提下这样做」。前提：功能完整和账号安全优先，不为了轻量砍功能或降低防风控能力；在这个前提下选最省资源的做法。具体做法：
    - 浏览器不常驻：要运行任务时才启动，跑完就关。空闲时只剩 Go 服务端在跑。
    - 同时打开的页面数默认 1，可以调大。
    - 不另外带运行时：服务端是一个 Go 程序（桌面端相关的要点随第 36 条搁置）。
    - （随第 36 条搁置）桌面端优先用电脑上已经装好的 Chrome 或 Edge，不自带浏览器。
    - 硬盘上的数据有上限：商品图片只缓存缩略图并设总量上限，旧结果按设置自动清理，日志自动轮转，限制浏览器缓存的大小。
    - 目标值（实验和实现时按实测校准，不是拍脑袋的承诺）：Docker 镜像压缩后约 350MB；空闲内存 50MB 以内；跑一个页面时浏览器约 0.5–1GB，容器至少给 1GB（依据见第 38 条）。
17. **限制和参数尽量做成配置项，不写死。** 用户原话：「这种配置项我觉得可以不用写死，而是作为一个配置项，做成默认值，然后在配置下面写明为什么要这样设置、推荐的设置，以及对应的风险」「尽量做得灵活一点」。具体：
    - 频率、额度、等待时间、每次打开详情页的上限、每小时浏览次数、同时打开的页面数、缓存时长、清理周期、图片缓存上限等数值，都是配置项。
    - 每个配置项在界面上都写明：默认值、为什么这样设、推荐范围、调到推荐范围以外会有什么风险。超出推荐范围时界面给出明显提示，但允许保存。
    - 只拦明显无效的值（比如 0、负数、间隔短到 1 秒），不设「安全下限」去替用户做主。
    - 默认值按账号安全定，偏保守；由我参考上游代码和 issue 研究决定（`AGENTS.md` 的分工）。
    - 不做成配置的只有行为底线：对闲鱼只读、不破解验证码、不改浏览器指纹、不自己拼签名直接调接口。这些是做不做的问题，不是数值。

作者原话：「这些技术细节，我感觉你完全可以通过查看现在的参考项目以及自己去调研来，自己就是确定这些问题啊……他很明显有最佳方案呀」。依据来自三方面：参考项目的源码和全部 331 个 issue（相关的约 80 个读了全文）；主流自托管项目的官方文档和源码；在作者 Mac 的 Docker 里实际装 Chrome、跑页面量出来的数据（测试页用的是京东首页，没有访问闲鱼）。

37. **动工前的实验只做可行性摸底**：粗看几件只有真实环境才能回答的事，比如 Docker 里的 Chrome 能不能正常用闲鱼、登录能保持多久、手动能不能过滑块、实际占多少内存。不再做「三个环境各跑一周」的频率测试：一个号测不出可靠的频率阈值，频率默认值按 `CRAWL-POLICY.md` 的证据定，上线后靠运行记录持续校准。客户端已搁置，所以只在 Docker 里测。做法见 `EXPERIMENT.md`。
38. **Docker 镜像**：
    - 基础镜像 `debian:trixie-slim`，按架构装 Google 官方的 `google-chrome-stable` deb 包。Google 的 apt 源已经同时提供 amd64 和 arm64，版本一致（2026-11-09 查过 `dl.google.com` 的源索引）。Chrome 在容器里不会自己更新，跟着镜像发版更新。
    - 中文字体用 `fonts-wqy-microhei`（安装后 5MB）；`fonts-noto-cjk` 要多占约 55MB，不用。Chrome 的语言包只留简体中文和英文，省约 13MB。
    - 实测体积：压缩后约 345–355MB（arm64）。参考项目的镜像压缩后约 430MB，selenium、browserless 这类通用镜像在 1GB 以上。图形库（约 62MB）先保留，因为是否需要 WebGL 要等实验结果（见下面 WebGL 一条）；实验确认不需要的话，再删掉图形库，压到约 300MB。不用 zstd 压缩：群晖等 NAS 上的 Docker 版本可能太旧，拉不了。
    - noVNC 只放它的静态网页文件，不装 Debian 的 `novnc` 包（会带进 nodejs、python3）。浏览器画面的 WebSocket 由 Go 服务端转发。
    - **用非 root 用户运行，支持 PUID/PGID**，解决参考项目「root 写进挂载目录的文件，普通用户删不掉」的问题（#364）。参考项目改非 root 时把浏览器路径弄错、目录没权限，两天就退回了 root（#370、#371、#374）；我们镜像里的 Chrome 路径固定，启动时由入口脚本按 PUID/PGID 修好数据目录的属主，避开这两个坑。
    - **保留 Chrome 的沙盒，不加 `--no-sandbox`**。实测：Docker 默认设置下，不加 `--no-sandbox` 的 Chrome 直接启动失败，因为 Docker 默认的 seccomp 规则不允许创建命名空间；而加了 `--no-sandbox`，页面顶部会出现警告条，`innerHeight` 少 56 像素，网页能看出来，渲染进程被攻破时也没有隔离。所以：
      - 官方 compose 文件默认带 `security_opt: [seccomp=unconfined]`，实测沙盒能正常工作，Unraid、群晖都能设置；另外提供一份只多放开创建命名空间的 seccomp 规则文件，给想要更严格隔离的人用。
      - 沙盒起不来时，服务端检测到后在页面上说清楚原因和改法，**不自动退回 `--no-sandbox`**：自动退回会让浏览器带上网页能看到的特征，违背账号安全优先。
      - 群晖 DSM 的内核可能不支持用户命名空间，这时只能加 `cap_add: SYS_ADMIN` 走 Chrome 的 SUID 沙盒，文档里单独写。
    - **去掉 `--disable-dev-shm-usage`**：Chromium 在 Linux 上已经改用 memfd 共享内存，不再依赖 `/dev/shm`（`platform_shared_memory_region_posix.cc` 的注释说正是为了容器里 `/dev/shm` 只有 64MB 的问题）。实测加了这个参数反而多占约 175MB 内存，所以也不需要设 `shm_size`。实验时再确认一次。
    - **内存**：实测打开京东首页（一个很重的电商页），浏览器约 330–400MB 私有内存加约 260MB 共享内存，容器峰值约 0.9–1GB；限制在 600MB 时页面进程被杀，800MB 能跑。所以文档写明：容器至少给 1GB，2GB 的 NAS 能跑但比较紧，同时只开一个页面（默认值本来就是 1）。闲鱼页面的实际数字在实验里量。分辨率影响很小，1366×768 只比 1920×1080 少约 30MB。
    - **虚拟屏幕**：Xvfb 设 `1920x1080x24`；每个 Chrome 一个独立的显示（第 61 条）；浏览器语言固定 `--lang=zh-CN`，Chrome 的时区（`TZ`）按设置项来，这是配置运行环境，不是改指纹。
    - **WebGL**：当前固定版本的断网容器实测，未映射显卡时默认 WebGL 不可用；自动软件回退的版本与安全背景见第 121 条，不按一个历史版本号推断所有平台。三种选择都不伪造任何东西，不违背「不改浏览器指纹」：不开 WebGL（默认）、用 Mesa 的 llvmpipe 软件渲染、NAS 有 Intel 核显时把 `/dev/dri` 映射进来用真显卡。哪种被闲鱼拦得少，在实验里对比「不开」和「llvmpipe」；不用 SwiftShader。
39. **网页端里的远程画面**（扫码、过验证时用）：
    - 需要时才启动 x11vnc，只监听容器内的 127.0.0.1，平时不运行；网页端通过已登录的 Kakatta 会话连到它，VNC 端口绝不对外暴露。x11vnc 用 X 服务器的 XTEST 把操作送进浏览器，用户的操作和真人一样走 X 服务器，不经过 CDP。
    - 用 noVNC 的核心库，但触摸操作自己处理。noVNC 默认在手指移动 50 像素后才按下鼠标，拖滑块时起点会突然跳 50 像素，轨迹不自然；双指缩放会变成 Ctrl+滚轮，把网页放大。所以：手指一碰就按下鼠标；禁止双指缩放网页；服务端知道验证码在页面上的位置，画面自动放大到验证码附近，手机上按 1:1 或更大显示。
    - KasmVNC、Selkies、Guacamole 都看过，依赖太重（实测 KasmVNC 光依赖就多约 118MB）；CDP 截屏流只能看到网页，看不到浏览器自己的弹窗，只在 x11vnc 起不来时作为只读画面备用（第 116 条）。
    - 用手机浏览器能不能真的拖过闲鱼的滑块，要在实验里验证。参考项目没有任何远程画面方案，用户反复报告「手动拖滑块也过不了」「验证窗口一闪而过」（#264、#289、#279），所以这一项对 Docker 部署是关键。
40. **服务端暴露到公网时的安全**：
    - **HTTPS 交给反向代理**：服务端只提供 HTTP，不内置证书申请。Immich、Jellyfin、Vaultwarden、Uptime Kuma 都是这样，Vaultwarden 的文档明确不推荐用它自带的 TLS；NAS 和家用网络里 80、443 端口常常被占或者没有，内置证书申请很难排查。文档写清 Caddy、Nginx、Cloudflare Tunnel、Tailscale 各自怎么配。有可信代理列表，只信任列表里代理传来的 `X-Forwarded-*` 头。从公网用明文 HTTP 访问时，页面上醒目提示。
    - **首次初始化要先填一次性令牌**：照 Portainer，第一次启动时在容器日志里打印一个一次性初始化令牌，网页上填对了才能设置账号密码；令牌 30 分钟有效，过期重启容器再拿新的。不这样做的话，服务器刚启动、暴露在公网上时，谁先打开网页谁就成了管理员（Immich 就有这个问题）。
    - **密码**：Argon2id（OWASP 首选），同时只算一个哈希，免得 2GB 内存的 NAS 被拖垮。
    - **防暴力破解**：只有一个账号，按账号锁定等于把主人自己锁在外面（OWASP 也这么提醒），所以按 IP 递增延迟，再加一个全局的失败次数上限；真实 IP 只从可信代理的请求头里读，避免 AdGuard Home 那种「在代理后面所有人被当成同一个 IP」的问题。连续失败会写系统事件并推送。
    - **会话**：Cookie 带 `HttpOnly`、`SameSite=Lax`；通过 HTTPS 访问时加 `Secure` 和 `__Host-` 前缀。30 天不用就过期，最长 90 天必须重新登录；登录后换新的会话 ID。
    - **跨站请求伪造**：用 Go 标准库的 `http.CrossOriginProtection`（Go 1.25 起），按浏览器发来的 `Sec-Fetch-Site`、`Origin` 头判断。gorilla/csrf 有漏洞（GO-2025-3884），官方建议迁移到这个。
    - **所有接口都必须登录**，包括 WebSocket 和远程画面。参考项目的登录只拦页面不拦接口，不登录就能读到账号 Cookie（#491，至今未修）。
    - **加密主密钥**：照 `DOMAIN.md` 2.2 节，第一次启动自动生成 `secret.key`。另外支持 `KAKATTA_SECRET_KEY_FILE` 指向一个文件，配合 Docker secrets（环境变量用 `docker inspect` 就能看到）。文档如实写明：主密钥和数据在同一个目录时，加密只能挡住「只有数据库文件泄露」的情况（比如把数据库发给别人排查问题），挡不住整个数据目录被拿走；浏览器配置目录里的闲鱼登录状态也在这个目录里。备份文件已经要求设备份密码（`DOMAIN.md` 15.4 节）。
    - 两步验证（TOTP）做成可选项，见第 44 条。
41. **多个闲鱼账号和代理**：保持 `DOMAIN.md` 第 6 节和 `PRODUCT.md` 第 2 节已经写的做法：同一账号同时只跑一个任务，同一账号的任务之间有最小间隔；全局同时打开的页面默认 1 个；每个账号固定绑一个代理或者不用代理，不轮换。依据：同一个号挂三四个任务就触发风控（#4）；作者认为同一环境里换号挡不住二次风控（#136）；机房 IP 更容易被风控（#10、#66）。参考项目的做法正好相反：没有按账号排队，几个任务同时触发就同时开几个浏览器；账号和代理每次随机选；拉黑名单只存在单次运行的进程里，下次运行就忘了。我们把账号状态（冷却、暂停）存在数据库里。
42. **闲鱼改版**：
    - 1.0 不做远程下发规则。规则仓库一旦被攻破，所有实例会同时收到恶意规则；对 Kakatta 来说，一个恶意或写错的选择器就可能让程序去点「立即购买」「聊一聊」，违背只读的底线。
    - 选择器、接口名、字段路径集中写在一个带格式版本号的数据文件里，打包进程序；闲鱼改版时快速发补丁版，配合第 43 条的更新提示（yt-dlp 也是靠快速发版应对网站改版）。
    - 主动发现改版：找不到关键元素、接口里找不到商品列表、连续几次解析出 0 个商品时，写一条「闲鱼页面结构可能变了」的系统事件并推送，让用户知道不是自己配置的问题。参考项目只能等用户报 issue，最长 6.5 个月才修好（#439）。

43. **更新**：
    - 镜像同时打精确版本号（`1.2.3`）、主版本（`1`）和 `latest` 三种标签，推荐用户固定版本号。参考项目只有 `latest` 和提交哈希，用户看不出自己是哪个版本（#64）。同时发布到 ghcr.io 和 Docker Hub，文档写国内的镜像加速办法（#407：拉了一个多小时）。

    - 启动时自动迁移数据库，迁移前用 `VACUUM INTO` 复制一份带版本号的数据库，只留最近几份；遇到比程序新的数据库就拒绝启动。退回旧版本等于恢复那份副本。文档写明：退回旧镜像时 Chrome 也会变旧，旧 Chrome 可能打不开新 Chrome 用过的配置目录，需要重新扫码登录。

59. **`chrome_crashpad_handler` 不靠参数关，靠目录可写和关浏览器时清理**（取代第 46 条里「有就加参数关掉」）：
    - 查到的证据：Linux 版 Chrome 在源码里强制打开 Crashpad（`kEnableCrashpad`，crbug.com/1176772），`--disable-breakpad`、`--disable-crash-reporter`、`--disable-crashpad-for-testing` 一起加也照样会起这个进程（chromium-dev 邮件列表、puppeteer #13419、cromite #941）；把它的程序文件删掉，Chrome 直接启动失败。

67. **人工登录不要求原接口重试，直接拒绝替换待验证状态**：
    - 登录会话里的新会话失效不是失败：用户还没扫码时接口可能本来就会返回失效，这正是当前会话要解决的事。验证码同样留在当前窗口给用户处理；直接拒绝或环境异常立即结束并按拒绝暂停处理。
    - （扫码完成条件已被第 131 条取代，其余验证与拒绝处理保留。）`XIANYU.md` 8.3 的三条条件满足后，还要有下列一项：本会话没见过会话失效；最后一次会话失效之后任意一个 mtop 接口返回成功；本会话可见的登录框出现过而现在消失。不要求同一接口返回成功，避免正常扫码后页面不重发旧接口而白等十分钟，也防旧 `unb` 造成误报。
    - 只按响应编号确认已经收到的验证或失效信号，响应头和正文分别确认；先后按实际到达顺序，不用请求发出顺序代替。人工接手之前已经发出、之后才返回的拒绝仍要拦住，早期验证码不能遮住后续拒绝。
    - 人工验证时遇到直接拒绝或环境异常，清空待验证标记、网址和旧冷却，由拒绝暂停状态接管。到期按 `DOMAIN.md` 7.2 恢复，不能残留假的待验证状态。
    - 用户确认验证完成时，当前页面已无验证遮罩且没跳登录页，才确认最后一次成功接口之前已收到的验证信号。之后没有成功响应的新验证继续拦住，提示用户在画面里刷新再确认；程序不刷新、不导航。直接拒绝和环境异常仍优先；发现登录失效就结束当前验证、清待验证标记，改走扫码登录，不清额度或原有冷却。
    - 依据是 `XIANYU.md` 8.2–8.3 的人工登录与旧上游登录框消失信号，以及 `DOMAIN.md` 7.2 的状态表。扫码后的刷新、接口重发行为尚未用真实页面确认，列入 `XIANYU.md` 第十一节。

68. **正式安全计算的参数和边界**（落实第 40、44 条及 `DOMAIN.md` 2.2–2.3）：
    - Argon2id 用 64 MiB、3 轮、4 路、16 字节盐、32 字节结果，Hash 和 Verify 共用一个进程内名额。采用 [RFC 9106 的内存受限推荐](https://www.rfc-editor.org/rfc/rfc9106.html#section-4)和 [Go 官方参数示例](https://pkg.go.dev/golang.org/x/crypto/argon2#IDKey)，不让异常 PHC 参数任意扩大内存。
    - 密钥文件保存原始 32 字节，环境变量才用 Base64；默认文件原子创建并同步落盘。显式来源错误不回退，已有数据库但密钥缺失时停止自动生成，避免把挂载错误当成新部署。
    - AES-256-GCM 用标准库随机 nonce 接口，保持原定存储格式和逐行 AAD。令牌采用 32 字节随机量及其 SHA-256，不在数据库存明文。
    - TOTP 为 SHA1、6 位、30 秒，允许前后一步；新增内部 `admin.totp_last_step`，和会话创建同事务条件更新，防并发与重启后重放。依据是 [RFC 6238 的一次性消费要求](https://www.rfc-editor.org/rfc/rfc6238.html#section-5.2)，不增加恢复码或额外产品选项。
69. **网页构建按 Safari 16.0，而不是 16.4**：Tailwind 4 的最低要求是 Safari 16.4，官方建议更早浏览器保留 3.4，所以使用 Tailwind 3.4，Vite 的脚本和样式目标都明确设为 `safari16`。接口描述用单一 `api/openapi.json`，字典用 `internal/locales/zh-CN.json`、`en.json`，前后端共用消息代码和 `{name}` 参数。依据：[Tailwind 浏览器要求](https://tailwindcss.com/docs/upgrade-guide#browser-requirements)、[Vite 构建目标](https://vite.dev/guide/build#browser-compatibility)，以及既定的第 22、30 条和 `TECH-STACK.md`。
70. **恢复探测固定 5，成功统计按单次请求的可用结果算**：`probe` 只检查服务商是否恢复，输出上限固定为 5，不套已有的 `max_tokens_floor`，不因截断重发或标成思考太长。`ai_calls.ok` 表示这次物理请求拿到了该用途可用的结果；2xx 但解析或校验失败仍记 false，usage 照记并计入每日额度；`probe` 按 2xx 算。依据是 `DOMAIN.md` 2.9 的最小恢复请求和 8.3 的探测截断例外，避免恢复检查无谓消耗输出额度，也避免成功率掩盖不可用结果。
71. **模型用量记录按既定花费上限处理，不新增持久票据**：每次实际请求前检查每日用量，请求结束后写一条 `ai_calls`；写入失败就停止本进程后续的模型请求。取得 usage 前进程崩溃，这次按没有返回 usage 处理，不做持久票据、整日封锁或未知用量状态。依据是 `DOMAIN.md` 8.8 已接受「缺 usage 按 0」和「已发出的完成，实际可略超」；这是用户的花费上限，与保护闲鱼账号的访问额度严格程度不同。
72. **无规格维度按不分配置比价，走势和合理价窗口分别计算**：合法任务可以只有必须满足而没有规格，配置键固定为 `*`，显示「不分配置」，不当作规格未知；没有去掉最后规格的放宽步骤。「较 14 天前」固定使用原配置最近 14 天每日中位数，价格带仍跟合理价当前采用的样本窗口走。最终合理价有半分时四舍五入到整数分，分位数和每日中位数不提前取整。依据是 `DOMAIN.md` 2.6 允许无规格任务、12.1 的配置与窗口规则及该列明确的 14 天名称。
73. **正式登录保护的具体参数**：按 IP 从失败后 1 秒起翻倍，最高 60 秒，15 分钟没有失败就清掉该 IP 的累计状态；被拦请求不延长等待。全局滚动一分钟最多 20 次失败，同时只接收 4 个待验证请求，并把在途请求占入全局名额，避免并发越过上限；Argon2id 计算仍只有一个。初始化、密码、验证码和安全设置的凭据验证共用保护。达到上限写 `login_failures`，下次完整登录成功解决；事件写失败先停止继续验证。数值是本项目的技术取舍，原则依据为第 40 条及 [OWASP 的节流、指数等待和避免锁死用户的说明](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#login-throttling)。内部 `auth.generation` 随密码、两步验证及维护命令换代，使另一进程执行维护后，尚未完成的验证码挑战和绑定也会失效，不伪造密码更改时间或额外吊销原本允许保留的会话。
74. **民用日界按实际存在的时刻计算**：额度和实验工具共用日界计算，不将 `time.Date` 归一化出的午夜再加一天。某些地区会跳过或重复午夜，甚至跳过一整天；按时区真实偏移区间找当天和次日首个存在时刻，防止旧日窗口提前结束。Go 的未来规则在转换之外可能只给合成年界，闰年末会出现不前进的终点；扫描必须严格前进并在下一 UTC 年界重查。依据是 [Go 的 Date 说明](https://pkg.go.dev/time#Date)、[ZoneBounds 说明](https://pkg.go.dev/time#Time.ZoneBounds)及标准库 `time/zoneinfo.go` 的 `tzset` 实现；已用午夜跳时、重复午夜、跳日和未来闰年末的回归核对，不改变第 64 条额度政策。
75. **自动整数编号删除后不复用**：全部自动分配的整数主键用 `INTEGER PRIMARY KEY AUTOINCREMENT`，固定管理员、迁移编号和自然或复合主键除外，清理不动 `sqlite_sequence`。普通 INTEGER PRIMARY KEY 删除最大编号后会复用；发现、任务、服务商和渠道的历史发送或用量引用有意保留且不全部设外键，复用会把旧历史挂到新对象，账号还涉及浏览器目录。为避免这些实际串线，接受每次插入维护序列的少量开销。依据：[SQLite 对编号复用与 AUTOINCREMENT 的说明](https://www.sqlite.org/autoinc.html)，并已用删除、重开及真实历史关联的红绿回归核对。
76. **清单项含义改变后，旧结论按版本失效而不删除**：必须满足、加分项和检查项各带内部 `rev`，新建为 1；判断用的条目文字，或自定义检查项的名称、判断说明改变时加 1，态度、问句、勾选和排序不变。事实和手动覆盖保存当时的版本；版本不同按 unknown，原内容保留，沿用新增检查项的重新分析提示。规格仍按原配置规则处理，不保存整份清单快照。程序按请求的清单补事实版本，不让模型或客户端任意回写计数；导入缺版本补 1。依据是第 48 条固定编号和第 63 条可编辑检查项：固定编号不能使「国行」的旧 met 自动变成「日版」已满足。
77. **任务保存、重新分析和中断恢复的边界**：省略任务名时取搜索词前 30 字，显式超长时报错；导入仍按第 15.1 节截断。切到关键词判断前确认清空需求清单且无法恢复，保存为空对象，不另藏旧清单；已有结论保留，待处理阶段随模式调整，不重置搜索基线。批量重新分析一律进入正常队列，只有单件可立即复用 24 小时详情；队列处理时缓存仍有效。运行开始保存未结束的保守占位，读取时显示正在运行；每账号在资源启动前保存内部会话标记，全部资源关闭并结算间隔后才清。启动恢复将未结束运行记为 restart，结束和账号间隔起点取保护后的启动时间，保留原已抽间隔与当前最小间隔中较大者，不恢复旧浏览器和手动队列。依据是 `DOMAIN.md` 2.6 的名称限制、4.6 的基线范围、5.5 与第 11 节的单件和批量重分析，以及 4.11 和第 64 条的重启保护。

## 2026-11-11（业务实现中的衔接）

78. **默认结果、全局隐藏和统计的准确事实**：默认结果是 AI 的捡漏、划算、价格合理、无法比价且非不建议，以及关键词命中，同时排除超预算、不感兴趣和屏蔽卖家；未推荐显示其余已有结论，尚未分析完的按状态筛选，隐藏另筛。孤儿商品清理保护不感兴趣标记，直到用户撤销或清除全部业务，屏蔽卖家仍不自动清理。每任务内部保存最近一次接纳搜索的准确商品编号集合，完成筛选的页面才可接纳，后页普通失败仍保留已完成页，零结果写空集合；不能拿最后见过时间猜“还搜得到”。连续跳过仍折叠成一条日志，但同事务另存逐次发生时间，供准确的小时和时间范围统计。依据是 `PRODUCT.md` 第 6 节、`DOMAIN.md` 第 11、12、14、16 节：隐藏不能因清理失效，最近搜索与发生小时也不能从已经丢失的信息推算。
79. **重发上限按每次逻辑提醒计算**：新增最小内部通知意图和投递关联，一次推荐、新商品、降价或升档分别保存失败次数、第一次全部失败时间和结算状态；发现不再重复维护 `notify_failures`，也不从该发现一生的最早投递推重试窗口。每次意图三次全部失败或超过二十四小时才终止；新的降价是新事件，不被很久以前的失败挡住。重新分析的来源在处理请求时持久保存，不能随排队时间清空而丢失。首次推荐价格 100 全部失败，下一轮变成 90 时，更新原待发推荐意图为 90，只发一条推荐，不同时另发降价；按基线等规则只记推荐基准的原规则不变。概览按成功的降价意图计数，多渠道或合并发送也只算一次。系统事件继续使用自己的状态，不扩大到意图表。依据是 `DOMAIN.md` 5.5、10、13.2–13.4、16 的来源、成功基准和去重要求。
80. **发现的异步处理另核工作版本**：`search_generation` 只区分搜索条件，挡不住同代中用户重新分析后旧请求回来覆盖新 pending。发现新增内部正整数 `processing_revision`，初始为 1，重新分析和待处理阶段模式迁移时递增；处理前捕获，保存标题、详情、失败或结论时同时核对任务代次、工作版本和预期阶段，过期结果不写。不用毫秒时间假充唯一版本，因为同一毫秒可有两次操作。服务端产生的内部次数沿用第 94 条，不逐处增加假想的溢出判断。依据是第 76、77 条的旧事实保留和重新排队规则，以及 `DOMAIN.md` 4.6、5.5 的取消与晚结果边界。
81. **图片准备先限制源资源，再做固定转换**：单源最多 20 MiB、四千万像素，先读取尺寸检查再完整解码；每个准备器跨任务总共最多三张同时下载，单图三十秒。按既定前 N 张取图，不从后面补失败图，不限制用户保存的图片张数。校正 EXIF 方向、透明合成白底，不放大小图，最长边 1024、JPEG 质量 80；原长边超过 4096 时先用最近邻缩到 4096，再用 Lanczos 缩到 1024，避免极细长图按原长边分配大量滤镜权重。转换只在内存，不因此缓存原图。使用 [imaging 的方向与缩放接口](https://pkg.go.dev/github.com/disintegration/imaging)避免重复写图像处理，资源限制依据 [Go 对不可信图片的说明](https://pkg.go.dev/image#hdr-Security_Considerations)。具体边界是控制容器内存和挂起请求的技术取舍，不是新增用户设置。
82. **手动规格和清单编号各自保住原始事实**：第二、三层不得覆盖手动规格的 `specs`、`brand_new`、`kind`、`source` 四项，`config_key` 与 `excluded` 仍按当前清单和有效事实重新派生，不改原 `updated_at`；同事务先更新样本排除资格，再算行情和分数。任务在判断模式间切换时，编号水位独立存 `task.profile_next_no.<id>`，关键词模式的清单仍为空对象，不藏旧清单；删除任务或清除业务时删水位。清单外发现迁成检查项时同样递增工作版本，防止在途旧结论抹掉刚迁的证据。依据是 `DOMAIN.md` 2.6、2.7、5.3 和第 76、77、80 条。
83. **账号事件跟随真实状态，退出不能绕过拒绝期**：离开 `needs_verification` 就解决 `account_verify`，转冷却、登录失效或拒绝也一样；失效和拒绝分别建自己的事件。拒绝期内退出仍删除浏览器资料，但保留拒绝原因与期限，另记内部已退出标记；到期后回到未登录，不能变成可用账号。登录成功或删除账号清标记，清除业务保留。依据是 `DOMAIN.md` 7.2 的状态优先级和拒绝暂停：旧验证事件不能盖过当前状态，退出也不能解除拒绝保护。
84. **没有取得评价，不能当作没有差评**：卖家四个计数缺失用空值，最近评价的未取得与明确取得空列表分别表示。只有确实取得评价后，才允许将没有核实风险显示为正常，并参与信用加分；取得资料但未取得评价时，相关检查项仍为不知道。已核对的评价证据照常生效。依据是 `DOMAIN.md` 2.7、5.8 的未知值与证据规则，不能因缺字段或请求失败白送分数。
85. **浏览器初始化后停用 Runtime，验收核对协议而非失效的网页判据**：每个目标只在 `about:blank` 初始化时允许一次 `self`，随后立即 `Runtime.disable`，失败就终止启动；后续不再启用，不主动运行页面脚本，也不修改指纹。子目标同样核查。验收在真实本地页面验证协议事件停用时为零、启用阳性时非零、再次停用时为零，并按阶段过滤缓存重放。旧 `Error.stack` getter 只留诊断，因为 [V8 的变更](https://chromium.googlesource.com/v8/v8/+/e08e97347454255a337dcea361808fb25ca09077)已避免在启用 Runtime 时执行该用户代码；通过只证明协议行为，不宣称网页无法识别浏览器。依据是 `CRAWL-POLICY.md` 第二节的初始化限制及实际阳性失效结果。
86. **预算未知与系统通知重试的准确边界**：设置预算上限但价格未知时不推送，原因是「价格未知，无法核对预算」，列表不能标成已知超预算。`none` 下无法比价不记录推荐价，未知比价例外只适用于 `good`、`fair`、`all_new`；实际分数达到门槛仍按原规则记基准。系统事件另存失败轮数和第一次全部失败时间，全部渠道失败时在下一次既有调度唤醒重试，三轮或超过二十四小时停止；任一渠道成功就不重发，不新增轮询。投递历史保存事件编号且不随事件删除。唯一显式指定的系统渠道删除返回冲突，提示先改设置；有其他目标时同事务移除该编号。任务引用不阻止删除，确认界面列出受影响及删除后没有渠道的任务。依据是 `DOMAIN.md` 13.2、13.4、13.5 和第 79 条。
87. **重新分析期间暂停旧推荐意图，恢复后消费来源标记**：旧推荐或新商品尚未送达时，重新分析处于待处理或失败就暂停发送；得到新结论后按当前预算、隐藏、屏蔽和全部推荐条件复核。通过的继续原意图及其失败窗口，不合格的取消并写原因，价格按当前实际值更新。完成这一轮终态复核时，同事务按工作版本消费重新分析来源标记；待处理、失败时不清，新的重新分析请求会再次置位，避免每次普通行情变化都重新判定。系统验证提醒中的保留期限只读当前活资源，取不到就省略该句。依据是 `DOMAIN.md` 5.5、13.2 的一次判定与第 79、80 条的耐久来源和旧结果保护。
88. **读取不偷偷推进时钟，清理不丢仍有效的每日用量**：统计、状态和查询只读已持久化的最高 UTC 时间，以其和当前时间较大者计算，并在内存推进日窗口，不为一次读取写库；额度申请等写动作仍同事务保存保护时钟。清理调用记录的起点取保留期与当前有效每日窗口起点较早者，保护夏令时长日和改时区留下的旧日窗口；统计覆盖起点只前进。依据是第 64、74 条和 `DOMAIN.md` 6.1、8.8、14 节，清理不能凭空恢复额度。
89. **继续降价沿用待发窗口，缓存清理不改变已核卖家结论**：待发降价从 90 再降到 85，更新原意图价格，仍沿原三轮和二十四小时窗口；放弃以后只有低于该放弃价格才允许新意图，同价或更高不新建，成功降价基准仍只在送出后更新。发现另存分析当时卖家检查项的状态和短证据，以及派生画像与信用加分资格，重算用这些结论，不再依赖会清掉的原始卖家数字缓存，真正重新分析才更新。折叠跳过日志有时间筛选时按逐次事件命中并显示窗口内次数，无时间筛选显示整行次数。依据是 `DOMAIN.md` 5.8、10、13.4、14、16 节：不能通过新建意图绕过失败上限，也不能因清理缓存把已有风险或加分抹掉。
90. **预算建议单独纠正，不让整份生成清单作废**：有效预算按最短十进制四舍五入到整数分；非数、非有限值、负数或超出整数分范围的，只去掉这个值；下限高于上限时两者都去掉。清单和其他建议照常使用，不为预算建议重试整次请求。内部诊断只保留固定字段名，供应用安全日志记录，不进入界面警告，也不保存原始值。依据是 `DOMAIN.md` 8.6 中建议必须由用户点选才填入的边界，及 15.1 的无效预算修正规则。
91. **接口请求客户端固定到保留递归 JSON 契约的版本**：采用 `openapi-fetch` 0.16.0。0.17.0 新加的读写标记变换会在本项目递归 JSON 类型上丢掉必需的 `default`，并将合法嵌套设置请求变成只许 `undefined`；已用实际客户端的读取和更新两例严格类型检查复现，固定版本后通过，不手改生成描述或用类型断言绕过。变更出处为[官方更新记录](https://github.com/openapi-ts/openapi-typescript/blob/main/packages/openapi-fetch/CHANGELOG.md)与[引入标记的改动](https://github.com/openapi-ts/openapi-typescript/pull/2549)，具体错误结论来自本项目的本地回归。
92. **切换判断方式时停止未完成的旧推荐**：在切换方式的同一事务里，已有结论尚未判定推送、或已经判定但尚未成功送出的发现，清空 `notify_kind`，`notify_skip_reason` 写「判断方式已修改」，取消待发意图。原判断结论、已发送历史和搜索基线保留，重新分析照 5.5、13.2 不发首次推荐。不推测旧判断方式或旧推送档位，也不新增档位快照。依据是 `DOMAIN.md` 2.6 保留原结论的要求与 4.6 对搜索条件变化的现有处理；避免把合法保留的旧结论当成新方式下的数据损坏。

94. **专用业务整数统一使用网页可精确表示的范围，不透明 JSON 用文本传输**：金额分、token 上限、时间戳毫秒、整数编号、计数和清单水位等接口整数范围为 `-9007199254740991` 到 `9007199254740991`；正数、非负数、账号容量、分页和等待时间等原有更严格边界保留。用户输入超出范围归为明显无效并返回字段错误；网页保留手输原文，不舍入、截断或提交错误值。这个金额上限约为九十万亿元，token 数、计数和本机编号也足以覆盖真实使用，因此不为这些字段引入另一套大整数传输和计算。服务端产生的编号、时间和内部次数不逐处加假想的溢出判断；闲鱼商品、卖家等字符串编号保持原文。Webhook 的 `body_template` 和 `query_params` 是写给外部系统的不透明 JSON，可能含合法的外部大编号，维持任意 JSON 语义；仅这两个字段在网页接口中改为 JSON 文本字符串，服务端验证后保留数值原文，网页不解成数值对象再提交。依据是 `DOMAIN.md` 第 3 节只拦明显无效值的原则、第 13 节 Webhook 的原有语义，以及 [ECMAScript 对安全整数及其范围的定义](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.max_safe_integer)。
95. **恢复不跨库猜账号，本机时间保护继续保留**：恢复后的数据库就是恢复后的状态，账号的访问额度、冷却和拒绝暂停不从本机旧库按 `account_id` 搬过去；备份按 15.4 不含 `quota_events`，恢复后访问记录为空。AI 用量只用备份里的 `ai_calls`，不合并本机当天调用，避免重复统计。本机最高已观察 UTC 和未结束的旧日窗口继续保留，不随恢复倒退。恢复的二次确认补充「访问额度和当天的 AI 用量会按备份里的记录重新计算」。依据是第 64 条额度保护的是用户自己的账号，以及 15.4 的全量覆盖、排空运行和全部账号重新扫码；不同数据库的自增编号不能证明账号相同，不为这次主动恢复增加跨库账号匹配机制。
96. **恢复候选先验证原库，再用私有副本补查约束**：先将上传库的完整结构和迁移链对照本仓可信迁移，拒绝被替换的表、约束、索引及额外视图、触发器或虚拟表；在原库只读连接做完整性和外键检查，不能让 `VACUUM INTO` 重建索引后掩盖原损坏。当前 `modernc.org/sqlite v1.62.0` 所带 SQLite 3.54.1 的 `sqlite3AddCheckConstraint` 不为只读 Btree 保留 CHECK 表达式，只读完整性检查会遗漏违反 CHECK 的行；因此再复制到独立私有库，以可写打开、`query_only=ON`、`trusted_schema=OFF` 补做完整性与外键检查。复制复用既有 `VACUUM INTO`，仅此时临时关闭源连接的 `query_only`，底层 `mode=ro` 始终禁止原库写入。临时副本结束即删除；原数据库和 WAL 字节保持，锁页不宣称零改动。依据是 [SQLite 完整性检查的范围](https://www.sqlite.org/pragma.html#pragma_integrity_check)、当前驱动源码及 `restore_validate_test.go` 中坏索引、坏 CHECK 两条独立回归，不另写数据库或 SQL 解析器。
97. **余额与当天额度错误每天最多自动探测一次**：从错误发生后的下一自然日起，余额不足和当天额度用完的已启用服务商每天最多发一次最小文字请求，直到成功或用户保存。仍是这两种错误时保持原状；网络错误和 5xx 不改状态，下一天继续。探测得到 Key 无效、模型不存在等明确需要用户处理的错误时更新原因，停止自动探测。用既有 `ai_calls` 的 `purpose = probe` 记录去重，窗口起点沿第 64 条、崩溃记账窗口沿第 71 条；等待名额后、实际外发前再次核对配置和资格，不因日限或本地连接配置失败用掉当天机会。依据是 `DOMAIN.md` 2.9 自动恢复的本意，以及其他永久错误须由用户处理的既有规则，不改请求客户端的错误分类。
98. **草稿新编号保持稳定，已存删除号不能复用**：重新生成和保存时，保留格式合法且不低于真实已存水位的新编号；未知且低于已存水位的编号仍拒绝。`next_no` 取真实已存水位、有效草稿水位、实际已用编号加一的最大值，版本只按真实已存清单计算。生成不落任务或推进数据库水位，保存时才持久化。草稿新号尚无历史事实，无须增加草稿缓存、签名或身份协议；例如水位 10 的草稿含 `b10`、`c11`，删掉 `b10` 后再次生成，`c11` 保持不变。依据是 `DOMAIN.md` 2.6 固定编号、删除不复用与第 76 条按真实含义维护版本的规则，避免编辑过程中给条目重新编号。
99. **恢复合并本机和备份的时间保护，候选必须有管理员**：恢复后的最高已观察 UTC 取本机、备份和当前 UTC 的最大值，两边在该时刻仍有效的旧日窗口都保留，并按恢复后的时区推进；重复窗口保留更早起点。不跨库合并账号访问记录或模型调用，避免合法备份里的调用被当成来自未来的损坏数据。备份候选必须包含管理员：导出接口须登录，本程序没有初始化前导出的来源；缺管理员按无效备份拒绝，原数据保持。依据是第 95 条保留本机时间保护、2.2 的统一鉴权和 15.4 的完整恢复，不新增恢复后转入初始化的路径。
100. **更新检查以服务端尝试时间为准，每二十四小时最多一次**：默认开启，由既有服务生命周期安排；读取状态不发请求，不增加手动检查入口。失败也记录尝试时间，下一次至少相隔二十四小时，重启和切换开关不重置；遵守远端更长的限流等待。固定读取本仓库的最新正式发布，只保存版本、链接、检查时间和条件请求标记，失败保留旧结果并标为过期，不假称已是最新。运行版本由发布构建写入，按完整 SemVer 比较，开发版本无法比较时保留未知；不把接口描述版本当运行版本。依据是第 43 条、`PRODUCT.md` 设置中的每日更新检查，以及 [GitHub 正式发布接口](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)、[条件请求与限流要求](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)和 [SemVer](https://semver.org/spec/v2.0.0.html)。
101. **表格导出保留已知结论，只转换危险文本单元格**：已经完成判断、因无法比价而没有分数的「不建议」仍导出已知配置和档位，分数、合理价自身未知就留空；关键词任务和尚未完成判断的四个评分字段仍空。供 Excel 阅读的 CSV 对首个有效字符为等号、加减号、`@` 或对应全角字符的文本字段加单引号，数据库原文不变，真正的数字价格不加；不宣称这种表格阅读转换适用于所有下游软件。依据是 `DOMAIN.md` 15.2 的已知值与中文结论要求，以及 [CSV 公式注入的格式限制](https://owasp.org/www-community/attacks/CSV_Injection)，不能为了空分数抹掉已经知道的不建议，也不能把卖家原文当表格公式执行。
102. **导入优先保留内容，修正不可信来源与编号并报告部分结果**：格式非法的固定编号按缺编号重新分配，保留条目内容；仅第 15.1 节明确要求去掉的未知非自定义风险等条目才去掉。`source` 缺失或非法按 `ai` 处理并列修正，必须满足转为加分项，未编辑的自定义严格档位降到 `mind`，不猜成用户硬条件。不认识的任务及嵌套字段去掉并列修正，重复字典风险留第一条；字段类型错误仍按原规则跳过该任务。中途存储失败保留已提交任务，返回 HTTP 200 的部分报告，`complete = false`，列出保存数量和未处理项，不自动重试。依据是 `DOMAIN.md` 15.1 的逐项修正、不中断其他任务和中途失败保留成果原则。
103. **恢复确认只消费完整验证过的一次性候选**：每个运行实例最多保留一份等待确认的候选，完整解密和校验通过后才替换旧候选；随机确认凭据绑定发起的登录身份和运行代，十五分钟失效。确认只消费一次，确认前及排空旧请求后再检查身份，运行代已变或身份失效就拒绝；恢复失败不自动重试已消费的候选。过期、替换、关闭时清理临时文件与内存密钥；确认成功后清理失败只记录待清理问题，不把已提交恢复报成失败。依据是 2.2 的会话吊销、15.4 的先检查后二次确认及失败保留原数据，不让网页提交路径或密钥，也不让重复点击重复恢复。
104. **退出登录和恢复都保留未到期的账号暂停**：手动退出和恢复候选共用同一退出规则：尚未到期的冷却或拒绝暂停保持状态、原因和截止时间，另记已退出；暂停到期后转为 `signed_out`，不能恢复为已登录。扫码、自动运行和手动运行都按真实截止时间检查，不能只看状态名；正常仍登录的冷却账号保留原有一次手动机会，已退出的账号不能使用。依据是第 7.2 节的冷却、拒绝保护和第 15.4 节全部账号重新扫码的要求，以及真实回归中「冷却 → 退出 → 扫码」原先绕过期限的问题。恢复仍只沿备份内账号状态，不跨库匹配账号（第 95 条）。
105. **恢复准备不写明文主密钥，启动清理中断留下的备份工作文件**：候选数据库落在数据目录内由程序标记所有权的私有 `.backup-work/`，从备份解出的主密钥只保存在内存；只有默认文件来源在确认切换时才写新的主密钥文件。导出快照也放在该工作目录。启动持两个锁，先处理持久恢复记录，再清理能确认属于程序的工作目录；保留未知文件并报错，不能只凭目录名认领。外部主密钥配置路径、链接和链接经过的路径都不能依赖会被清理或搬动的位置。依据是第 15.4 节的分块处理、外部密钥规则和第 103 条的一次性候选，进程中断后候选已失效，不应保留快照或让恢复后的下一次启动找不到密钥。
106. **备份请求只访问鉴权通过时的运行代**：导出、准备恢复和确认都绑定请求进入时的运行代，取得快照的锁内核对代次。切换时取消旧代的导出和准备请求；确认可以在切换后完成响应，但排空后仍用旧代凭据再次检查。备份操作自身可能等待切换锁，不计入切换等待的普通请求，避免确认等待自己。依据是第 2.2 节的鉴权与会话吊销、第 103 条的候选身份，以及第 15.4 节恢复后所有旧凭据失效；取消未及时送达也不能用旧会话拿到新库的快照。
107. **合法历史消息翻不了时保留原文**：导出仍翻译当前认识且参数匹配的消息；旧代码或旧参数无法翻译时，在原字段写入消息的 JSON，保留代码、参数和数字原文，继续做 CSV 或制表符转义。真正损坏的 JSON、查询或写入失败才拒绝整份导出。网页的运行日志和结果原因可显示消息代码和「旧版本消息」提示，其他行仍正常显示。依据是第 15.2、15.3 节导出当前筛选的全部记录和第 96 条不重写历史，不因字典升级丢掉合法的旧数据。

第 104 条的网页提示：已退出但仍处于暂停的账号显示「暂停到 {时间}，之后需要重新扫码登录」，不显示冷却期间的手动检查机会。第 106 条的排空会取消旧请求，并中断阻塞的网络读写；如果三十秒内仍未排空，就保留旧运行代，不切换文件。

## 2026-11-11（主流程回归）

120. **失败暂停结束后保留真正能运行的时间**。清除已到期的失败暂停时，同事务把 `next_run_at` 保持在原计划和暂停结束时间的较晚者；更晚的原计划不提前，失败计数仍在运行成功后清零。否则先清掉暂停会让两小时前的旧计划，排在一小时前就能运行的任务前面，违背 `DOMAIN.md` 6.2 的实际可运行时间排序。已用两个账号竞争唯一页面名额的失败回归核对，并覆盖没有计划和原计划更晚的情况。

126. **卖家文字只作数据，固定系统说明和客观规则共同约束模型**。标题、描述、卖家昵称和评价继续以独立 JSON 字段发送，不插入系统消息。四类请求统一在有效模板之后追加 `DOMAIN.md` 8.6 的固定说明，试分析同样经过该构造入口；行情规格和用户采纳的清单外发现可能携带派生文字，所以也覆盖行情解读和需求清单。卖家画像仍由程序计算，不另发画像请求。内置原文和已保存模板不覆盖；提示词页以只读方式展示实际附加段，并用中英文说明「每次请求都会自动附加，不能修改」。
