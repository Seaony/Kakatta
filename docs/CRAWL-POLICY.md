# 抓取与防风控规则

2026-11-10 定稿（待实验校准）。依据：

- 上游 ai-goofish-monitor 源码（`src/scraper.py`、`src/failure_guard.py`、`src/rotation.py`、`src/services/search_pagination.py`），以及它的全部 331 个 issue：110 个读完了正文和评论，77 个和风控有关；PR 读了 26 个。
- 其他 9 个闲鱼开源项目的源码和 README。
- Chromium、chromedp 源码，Chrome 官方文档，以及第三方识别实测。

本文写的是「默认怎么做」。所有数值都是配置项（`DECISIONS.md` 第 17 条），界面上显示本文的理由、推荐范围和风险。

## 一、最重要的三条结论

1. **没有被证实安全的频率，只有「越慢越好」。** 上游作者原话：「频率没有一组可以保证不触发风控的数字……只是降低速度，不是白名单」（#473、#496）。
2. **打开商品详情页是风险最高的动作。** #516 搜索列表能正常拿到 30 条，详情页逐个被拦；#147 第 4 个详情就触发；作者建议「详情不要一次翻很多页」（#473）。
3. **一出验证就停，是唯一被反复证实有用的做法。** 重启、立即重试、同一环境换号重试都会马上再次触发（#19、#136、#348、#509）。

## 二、浏览器怎么跑

### 用什么浏览器

- **Google Chrome 正式版，开有界面的窗口。** 不用 Chromium，因为 Chromium 缺少 H.264/AAC 解码器，本身就和普通 Chrome 不一样。也不用任何无头模式：旧版 chrome-headless-shell 和完整 Chrome 的 `--headless=new` 都会在 UA 里带上 `HeadlessChrome`（Chromium `components/embedder_support/user_agent_utils.cc`）。goofish-cli 等至少 3 个项目记录了无头模式会被闲鱼判为「非法访问」，上游作者也建议关闭无头（`scraper.py:753`）。
- **服务器、NAS 和 Docker**：Chrome 跑在 Xvfb 虚拟屏幕上，屏幕显式设为 `1920x1080x24`（不设时默认是 1280x1024）。**每个 Chrome 一个独立的 Xvfb 显示**，显示编号按账号分配（`:100 + 账号 id`），`1920x1080x24` 是每个显示的大小（`DECISIONS.md` 第 38 条）。Chrome 固定传 `--window-position=0,0` 和 `--window-size=1920,1080`，铺满它自己的虚拟屏幕。这样几个账号同时运行时窗口不会叠在一起，远程画面里也只会看到一个账号的窗口（第五节）。Google 的 apt 源从 2026-07 底起同时提供 amd64 和 arm64 的正式版 Chrome，所以两种镜像用的是同一款浏览器。镜像、沙盒、内存和 WebGL 的做法见 `DECISIONS.md` 第 38 条。
- 桌面端先不考虑（`DECISIONS.md` 第 36 条）。注意：如果以后做桌面端本机模式，Chrome 要开在用户真实的屏幕上，每次抓取都会弹出窗口，到时候要先解决这个问题。
- 每个闲鱼账号有一份独立、长期保留的浏览器配置目录（user-data-dir），和用户自己日常用的浏览器完全分开。

### 怎么连浏览器（chromedp）

- **用固定端口连接，只绑定 127.0.0.1**，不用 chromedp 默认的 pipe，也不用端口 0。Chromium `content/child/runtime_features.cc` 规定：`--enable-automation`、`--headless`、`--remote-debugging-pipe` 和端口 0 都会把浏览器标记为「被自动化控制」（`navigator.webdriver = true`）；指定固定端口则被视为「人在调试」，浏览器保持正常状态。这是浏览器本身的行为，不注入脚本，也不加 blink 参数，不违反「不改指纹」的底线。
- 调试端口只在容器或本机内部使用，不映射到外面。每个账号的端口按账号 id 分配在一段不常用的高位端口里：`20000 + 账号 id`。不用 9222：它是调试端口的常见默认值，别的工具和扫描最先找它；也避开 Linux 给出站连接临时分配的 32768–60999，免得被占用。
- **启动参数**以 chromedp 的 `DefaultExecAllocatorOptions` 为基础（`allocate.go:90`）：
  - 去掉 `headless`（连同它附带的 `hide-scrollbars`、`mute-audio`）、`enable-automation`、`disable-extensions`、`disable-background-timer-throttling`、`disable-backgrounding-occluded-windows`、`disable-renderer-backgrounding`、`force-color-profile=srgb`、`disable-popup-blocking`、`disable-ipc-flooding-protection`、`enable-features=NetworkService,NetworkServiceInProcess`、`disable-features=Translate,BlinkGenPropertyTrees`。这些会改变浏览器的行为或者本身就是自动化特征。关翻译没有必要：浏览器语言固定是 `zh-CN`，打开中文的闲鱼页面不会弹翻译。
  - 保留 `no-first-run`、`no-default-browser-check`、`disable-background-networking`、`disable-breakpad`、`disable-sync`、`disable-default-apps`、`disable-client-side-phishing-detection`、`metrics-recording-only`、`safebrowsing-disable-auto-update`、`password-store=basic`、`use-mock-keychain`、`disable-hang-monitor`、`disable-prompt-on-repost`。页面基本读不到这些参数。
  - **不加** `--disable-dev-shm-usage`：Chromium 在 Linux 上已经改用 memfd，不依赖 `/dev/shm`，实测加了反而多占约 175MB 内存（`DECISIONS.md` 第 38 条）。
  - **不加** `--no-sandbox`：会出现网页能看到的警告条；容器里靠 seccomp 设置让沙盒正常工作（`DECISIONS.md` 第 38 条）。
  - 加 `--lang=zh-CN`，固定不变，不跟 Kakatta 的界面语言走：浏览器语言会出现在请求头和页面能读到的 `navigator.language` 里，用户切换界面语言时，闲鱼看到的环境不该跟着变。启动 Chrome 时把它的 `TZ` 环境变量设成设置项 `general.timezone`。
  - Chrome 子进程固定 `GTK_IM_MODULE=xim`、`XMODIFIERS=@im=none`，让远程 Unicode 输入使用本地 XIM，避免 GTK 动态键盘映射缓存尚未刷新时丢字。沿用镜像已有模块，不添加输入等待、重发或 CDP 输入；本地按键和 Navigator 对照见第 123 条。
  - 加 `--hide-crash-restore-bubble`：上次没正常退出时，不弹「恢复页面」的提示条。
  - `chrome_crashpad_handler` 在 Linux 上用参数关不掉，不去关它，改为保证它不出问题：给它可写的目录，关浏览器时把残留进程一起结束（`DECISIONS.md` 第 59 条）。
  - 另加 `--disk-cache-size`，按配置项限制每个账号浏览器的磁盘缓存（`DOMAIN.md` 第 3 节，默认 256MB）。
  - **不加** `--disable-blink-features=AutomationControlled`：它本质上就是在改 webdriver，有界面时还会弹出「不受支持的命令行标记」提示条。
- **不往闲鱼页面主动执行脚本**：读数据靠 CDP 网络事件（`Network.getResponseBody`），找元素靠 DOM 查询，点击和输入用 `Input.dispatchMouseEvent` 和 `Input.dispatchKeyEvent`，坐标取元素中心附近的随机点。每个目标只在 `about:blank` 初始化时执行一次 `self`，随后立即停用 Runtime；初始化失败就终止启动（第 85 条）。
- **chromedp 的坑**（实现时必须处理）：
  - 事件回调里不能阻塞，取响应正文要放到别的 goroutine 里；
  - 要等 `loadingFinished` 之后再取正文；
  - 截屏流每一帧都要回复 ack，否则积压 3 帧后就停止发送；
  - 事件队列容量是 4096，源码里有一条「队列满时可能死锁」的 TODO（`target.go:114`）。

### 浏览器什么时候开

- 要运行任务时才启动，跑完就关（`DECISIONS.md` 第 16 条）。登录状态保存在配置目录里，重开浏览器不会丢。
- **启动前清旧锁**：先确认这个账号没有 Chrome 进程在跑（按命令行里的 `--user-data-dir` 查），再删掉配置目录里的 `Singleton*` 文件（`SingletonLock`、`SingletonSocket`、`SingletonCookie`）。容器重建后主机名变了，旧锁会让 Chrome 以为别的机器在用这个目录，拒绝启动。有进程在跑时不删，这次启动失败。
- **关闭**：先用 CDP 的 `Browser.close` 让 Chrome 正常退出，把登录状态写回配置目录；10 秒内没退出，再结束整个进程组（`DECISIONS.md` 第 59 条）。
- 内存：实测打开一个很重的电商首页，容器峰值约 0.9–1GB，容器至少给 1GB（`DECISIONS.md` 第 38 条）。闲鱼页面的实际数字在实验里量。

### 代理

- 每个账号固定一个代理或者不用代理（`PRODUCT.md` 第 2 节），启动 Chrome 时用 `--proxy-server` 传进去。
- **带用户名密码的代理**：Chrome 的 `--proxy-server` 不支持在参数里写认证信息，SOCKS5 认证更是完全不支持。所以由 Go 服务端给这个账号起一个只监听 127.0.0.1 的本地转发代理，Chrome 连它（不需要认证），它再带着用户名密码去连用户的代理。HTTP 和 SOCKS5 都这样处理。转发代理按域名去连，域名由用户的代理解析，和 Chrome 直接用代理时一样，不在本机查 DNS。它和这个账号的 Chrome 一起启动、一起关闭。

## 三、怎么浏览

一次运行的路径：

1. **打开首页**，停留 2–5 秒，随机滚动一次，再等「普通操作之间等待」（1–3 秒）。
2. **在搜索框里逐字输入关键词**，每个字间隔 50–130 毫秒，然后回车。不直接打开搜索结果的网址：voltwake/xianyu-monitor 实测，直接打开搜索页会被 baxia 拦截，在搜索框里输入则正常。
3. **点筛选条件**（发布时间、个人闲置、包邮、地区、价格），流程见 `XIANYU.md` 5.5 节。发布时间在页面上一律点「最新」，「N 天内」交给第 5 步的本地筛选。每次点击之间等 1–3 秒。开关类筛选失败时不重复点击。
4. **读第 1 页结果**，必要时再翻页，页与页之间等 10–15 秒。
5. **先用搜索结果里已有的信息做本地筛选**：价格、排除词、地区、发布时间；AI 任务再加上固定开启的第二层，用文字模型批量整理标题（`DECISIONS.md` 第 49 条）。搜索结果里本来就有标题、价格、地区、卖家昵称、主图、发布时间、想要人数和标签（上游 `src/parsers.py`）。
6. **只给通过筛选的商品打开详情页**，每次运行有数量上限。打开前等 3–6 秒，看完后停留 10–20 秒。
7. **卖家主页**：AI 任务在卖家资料没有缓存或缓存已过期时打开，关键词任务不打开（`DOMAIN.md` 4.9）。卖家资料缓存 24 小时；卖家主页不往下滚动加载更多。

第 5、6 步是和上游最大的区别：上游对每一个新商品都打开详情页，而且每次运行没有数量上限（`scraper.py` 975–1198 行）。

## 四、风控信号和处理

### 识别

每次页面跳转后、每次操作后、每次收到接口响应时都要检查（信号的完整清单和检查位置见 `XIANYU.md` 第四节）：

| 信号 | 判定 |
|---|---|
| 网址含 `passport.goofish.com` 或 `mini_login` | 登录失效。注意：同一个弹层可能是验证码，也可能是掉登录（#111），必须按网址区分 |
| 主框架网址含 `punish` 或 `_____tmd_____`（含 `action=deny` 的按直接拒绝） | 需要人机验证 |
| 可见的 `div.baxia-dialog-mask` 或 `J_MIDDLEWARE_FRAME_WIDGET` | 需要人机验证 |
| 接口 `ret` 含 `FAIL_SYS_USER_VALIDATE` 或 `RGV587` | 需要人机验证 |
| 接口 `data.url` 含 `punish` 且 `action=captcha` | 需要人机验证 |
| 接口 `data.url` 含 `punish` 且 `action=deny` | **直接拒绝**，不给验证机会 |
| 响应头 `bxpunish: 1`（接口响应和页面文档本身的响应都查） | 被处罚 |
| 页面出现可见的「非法访问」「请使用正常浏览器访问」 | 环境被识别（#339），**按直接拒绝处理**。也可能是请求头错配（#509），所以我们不改任何请求头 |
| 接口 `ret` 含 `FAIL_SYS_SESSION_EXPIRED` | 登录失效 |
| `FAIL_SYS_TOKEN_EXOIRED` / `EXPIRED` / `EMPTY` | 令牌过期，页面会自己刷新，忽略这条响应 |

只认网址和可见内容，不能因为页面加载了 baxia 的脚本就判定为风控：每个正常页面都会预加载它（GooFish-AIMonitor 的经验）。

### 处理

- **风控错误必须一路传到最外层，立即结束整次运行。** 上游有个 bug：详情页触发验证后抛出的风控异常，被外层通用的 `except Exception` 吞掉了（`scraper.py` 详情处理段），日志写着「程序将终止」，实际却继续打开下一个商品（#516 的日志里连续约 10 个都被拦）。我们的实现要有专门的测试，保证风控错误不会被任何一层吞掉。
- **需要人机验证**：
  - 这个闲鱼账号上的所有任务立即暂停，推送通知给用户；
  - **保留这个 Chrome 等用户处理**：运行照样结束，但浏览器先不关，最多保留 `crawl.verify_hold_minutes`（默认 30 分钟）。验证框就在这个页面上，用户这段时间里打开远程画面就能直接处理，不用重开页面、多一次访问。保留期间这个 Chrome 照样占一个全局页面名额。到时间用户还没来处理就关掉；用户已经打开远程画面在处理的，从打开时起按过验证的会话算（`XIANYU.md` 第八节，10 分钟没完成就关）；
  - **保留期过后再「去验证」**：用户点「去验证」时，用同一个配置目录重开 Chrome，打开当时触发验证的网址，计一次访问（详情页、卖家主页的网址算详情类，其余算搜索类；额度用完也允许，因为是用户主动操作）。这次会话同样按过验证的会话处理。页面上看不到验证框时（重开后闲鱼不一定再弹），提示用户在远程画面里自己刷新一下页面；
  - 不重试，不在同一环境里换账号重试（#136：「爬虫浏览器环境和ip都没变」，换号没用）；
  - 用户处理完验证后进入冷却期，冷却时间默认逐次加倍：第一次 2 小时，再触发就 4 小时、8 小时，最长 24 小时；连续 24 小时没有再触发，就恢复到 2 小时。依据：goofish-cli 建议停 2–6 小时，xianyu-low-price-alert 逐次翻倍、最长 6 小时，上游的熔断默认 24 小时（#363）；
  - 冷却期内，允许用户手动「立即运行」一次（沿用 Mekke）。
- **直接拒绝**（`action=deny`，以及页面上出现「非法访问」「请使用正常浏览器访问」）：账号转为被拒绝访问，暂停 `crawl.deny_pause_hours`（默认 24 小时），推送通知。「非法访问」这类提示说明浏览器环境被识别了，运行失败类型记为 `risk_env`（`action=deny` 记 `risk_deny`），推送正文提示用户检查 WebGL 设置、Chrome 沙盒是否正常、代理是否可用。两种都不计入普通失败保护。
- **登录失效**：账号暂停，直到用户重新扫码登录。
- **普通失败**（网络、超时、页面结构变化）：同一个任务连续失败 3 次，暂停 30 分钟并推送通知（沿用 Mekke）。不和风控混在一起算。

## 五、登录和人机验证交给用户

- **登录**：在这个账号自己的浏览器里打开闲鱼登录页，用户扫码。登录状态由浏览器自己保存、自己续期，不导入导出 Cookie。上游靠导入 Cookie 文件，登录状态「快的时候不到半小时，慢的时候也就几个小时」就失效（#492）；我们这种方式能撑多久，要放进实验里验证。
- **服务器、NAS 和 Docker**：需要用户操作时，临时启动 x11vnc 加 noVNC，用户在网页端里直接看到并操作这个 Xvfb 窗口（手机上的触摸处理见 `DECISIONS.md` 第 39 条）。x11vnc 只接需要用户处理的那个账号的 Xvfb 显示（第二节：每个 Chrome 一个显示），用户在远程画面里只看到这个账号的窗口，看不到同时在跑的其他账号。鼠标操作经过 X 服务器送进浏览器，和真人操作走同一条路，不经过 CDP。用户操作完就关掉。noVNC 是静态网页文件，x11vnc 只有几 MB，平时不运行。
- **远程画面启动失败**：x11vnc 无法启动时，原浏览器的网页截图可作为只读画面，登录和验证的实际操作要等 x11vnc 恢复。页面会提示故障原因，以及重启容器和查看日志的办法（`DECISIONS.md` 第 116 条）。
- **扫码登录和过验证的会话当成一次运行处理**：和这个账号的任务互斥，占全局页面名额，10 分钟没完成就关掉；额度用完时也允许，照样计数。步骤见 `XIANYU.md` 第八节。运行中出现验证时，浏览器先保留一段时间等用户处理（第四节）。
- **在同一个浏览器里完成验证**：有 issue 报告，验证通过后拿到的 `x5sec` 和完成验证的浏览器绑定（xianyu-super-butler #62）。
- **风险**：上游作者确认「playwright的chromium 即使手动拖动滑动条做验证也无法通过」（#62）。我们的环境不同：正式版 Chrome、没有自动化标记、鼠标走 X 服务器，但能不能通过，仍然要用实验验证。

## 六、默认值（全部可改）

「每个账号」指一个闲鱼账号。

**一次「访问」怎么算**：只算会让闲鱼产生请求的动作，比如打开首页、提交搜索、点一个筛选、翻页、打开详情页或卖家主页、在卖家主页里点「信用及评价」；失败和重试也算。逐项清单见 `DOMAIN.md` 第 0 节和 `XIANYU.md` 5.8 节。

**单个动作内部的细节**不做成配置项：它们只影响单个动作像不像手动操作，不影响访问频率。实现时照下面的数值做：

- 点击：落点在元素中间 60% 的范围里随机取；鼠标从当前位置分 6–13 步移过去，每步之间停 8–25 毫秒，先快后慢；按下到松开 60–160 毫秒。
- 回车、Tab、退格这类功能键：按下到松开 50–120 毫秒。
- 滚动：一次滚动分 3–5 下滚轮事件滚完，每下之间停 80–220 毫秒。首页那一次随机滚动向下滚 200–700 像素（照上游 `scraper.py:701`）。

**同一账号同时只开一个页面、同时只跑一个任务**（`DECISIONS.md` 第 41 条）。这是行为，不是数值，不做成配置项：上游同时挂三四个任务就触发（#4），同一账号多个页面并行明显不像真人。

## 七、给用户的提醒（写进界面和文档）

- 机房 IP（云服务器、VPS）比家用网络更容易被风控（#66、#69、#223），NAS 放在家用网络里最好。云服务器上运行时，建议给闲鱼访问配一个住宅代理。
- 新注册的闲鱼账号更容易触发风控（#324、#339），最好用老账号。
- 网页版搜索比 App 慢大约 30 分钟（#490），Kakatta 不适合「秒抢」。
- 用来监控的闲鱼账号，可能因为风控被要求验证，甚至被限制。建议不要用你的主力账号。

## 八、要用实验验证的

动工前只做可行性摸底（`DECISIONS.md` 第 37 条，做法见 `EXPERIMENT.md`，编号和那里一致）：

1. Docker 里有界面的 Chrome 加 Xvfb，能不能正常扫码登录、搜索、打开详情，不被判为异常；WebGL「不开」和「llvmpipe」两种设置哪种更好。
2. `XIANYU.md` 第十一节里待用真实页面确认的选择器、接口字段和页面行为。
3. 扫码登录后，登录状态能保持多久，重启容器后还在不在。
4. 用户通过网页端的远程画面手动拖滑块（电脑和手机浏览器），能不能通过。
5. 闲鱼页面实际的内存占用和镜像体积，用来校准 `DECISIONS.md` 第 16 条的目标值。

不在动工前回答的：

- **按默认值跑多久会触发验证**：一个号、几天时间测不出可靠的阈值。默认值按本文的证据定，上线后靠运行记录和用户反馈持续校准。
- **搜索框输入和直接打开搜索网址的区别**：只有一个账号，比较两种做法要在同一个号上多冒一次险。默认用搜索框输入（有其他项目的实测支持）。

### 新号怎么用

作者提供的是新注册的闲鱼账号（`DECISIONS.md` 第 33 条），新号更容易触发风控（#324、#339）：

1. **先养号 1–2 周**（推测，没有直接证据，但这是成本最低的保护）：
   - 在手机闲鱼 App 里正常使用：每天打开、搜几次、看几个商品；
   - 把资料补完整；App 提示实名认证就按提示做；
   - 这段时间不跑任何自动化。
2. **实验时访问量很小**：每次由实验工具按正式流程跑一次搜索、打开两三个详情，作者在远程画面里看着（`EXPERIMENT.md`），分几天做，只在白天。
3. **同一时间只在一个地方用程序登录这个号**：同一个账号同时出现在两台机器的程序里，本身就是异常。
4. **手机 App 照常登录使用**：作者手动刷闲鱼不受影响，反而让账号看起来更正常。
5. 一旦触发验证，按第四节处理，并在实验记录里写清楚当时做了什么、什么时间。
